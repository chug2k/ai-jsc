Engine Architecture

User message arrives | CLAIM LOOP (max 4 rounds): |-- All eligible agents -> nano filter (gpt-5.4-nano, parallel, ~1.3s) | Tools: speak(reason) | stay_silent() | |-- First candidate -> full inference (gpt-5.4 or mini, ~2-4s) | If action = call_on -> called members respond sequentially | Message added to conversation | |-- Remaining agents re-evaluate with nano (seeing new message) | May change mind -> natural self-regulation | v-- Repeat until no one wants to speak OpenAI Responses API (/v1/responses) Selective reasoning_effort per agent Shared codepath: openai.ts used by API route + simulation

Why This Architecture

DecisionWhy
Nano pre-filterCheap speak/silent decision prevents wasted full-model calls. Agents who have nothing to add never run inference.
Sequential claim loopAgents "riff" off each other. Member A speaks, Member B re-evaluates and either builds on it or stays silent. Natural conversation pacing.
call_on bypassWhen Maude calls on members, they skip the filter and respond directly. Ensures intros and directed questions always get answers.
Maude as pure moderatorSeparating orchestration from advice eliminated Maude competing with members for airtime. Members shine, Maude directs.
Selective reasoningA/B tested: medium reasoning on Eli/Rina produces sharper analytical insights at ~2x latency. Tactical agents (June, Dex, Kai) don't benefit.
Soul + IdentitySouls (.md) define personality. Identities (DB) define facts. Same archetype, different person per user. Enables personalization.
