# Marketing metrics

You are the metrics collector for jobsearch.quest's marketing agent. This
skill runs on its own daily Claude Code routine, separate from
`/marketing-run`. Its only job: pull attribution data from PostHog and
leave a clean, ranked table in `content/marketing/METRICS.md` so that the
next `weekly_review` has real numbers to reason about.

## Environment

The routine must set these env vars in its cloud environment:

- `POSTHOG_API_KEY` — personal API key (phx_...) with `query:read` scope
- `POSTHOG_PROJECT_ID` — numeric PostHog project id
- `POSTHOG_API_HOST` — optional, default `https://us.i.posthog.com`
- `POSTHOG_CONVERSION_EVENT` — optional, default `session_started`
- `METRICS_WINDOW_DAYS` — optional, default `7`

If any required env is missing, the fetch script exits with a clear
message — surface that to the user and stop.

## Steps

### 1. Pull metrics

```bash
node scripts/fetch-posthog-metrics.mjs
```

The script prints JSON to stdout with this shape:

```json
{
  "window_days": 7,
  "conversion_event": "session_started",
  "pageviews": [{ "campaign": "2026-04-14-short_post", "count": 42 }],
  "conversions": [{ "campaign": "2026-04-14-short_post", "count": 3 }]
}
```

Capture the JSON. If the command exits non-zero, stop and surface the
error — do not invent numbers.

### 2. Read the index

Read `content/marketing/INDEX.md` to get the canonical list of shipped
artifacts (date, routine, angle). Build a lookup by campaign slug
(`<YYYY-MM-DD>-<routine>`) → { date, routine, angle }.

### 3. Merge and score

For every campaign slug that appears in either `pageviews` or
`conversions`, compute:

- `views` = pageviews count (0 if absent)
- `converts` = conversions count (0 if absent)
- `rate` = converts / views (as percentage, blank if views = 0)
- `score` = simple rank: views * 1 + converts * 25. Tune later based on
  what the weekly_review finds useful.

Sort by score descending.

### 4. Rewrite METRICS.md

Overwrite `content/marketing/METRICS.md`. Structure:

```markdown
# Marketing metrics

Last refreshed: <YYYY-MM-DD HH:MM UTC>
Window: last N days · Conversion event: `<event name>`

Auto-generated by `/marketing-metrics`. Weekly_review reads this to
score outputs and update MARKETING_PLAN.md.

## By campaign (ranked by score)

| Rank | Date | Routine | Angle | Views | Converts | Rate | Score |
|------|------|---------|-------|-------|----------|------|-------|
| ... rows, newest-data-first within ties ... |

## Totals

- Total views across tracked campaigns: N
- Total converts across tracked campaigns: N
- Top campaign: <slug> (<score>)
- Bottom campaign: <slug> (<score>)

## Unknown campaigns

Any utm_campaign values from PostHog that aren't in INDEX.md:

- `<campaign>` — views: N, converts: N

(These are usually typos or manual posts. If any recur, investigate.)
```

Keep the file under 200 lines. If there are more than 50 campaigns, keep
the top 30 by score + the 10 most recent by date.

### 5. Commit and push to main

```bash
git add content/marketing/METRICS.md
git commit -m "marketing(metrics): refresh — <N> campaigns, <total views> views, <total converts> converts

Session: https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID}"
git push origin main
```

Rebase-and-retry on push rejection, same as `/marketing-run`.

### 6. End with a one-line summary

```
metrics: <N> campaigns tracked, top <slug> (<score>), window <N>d
```

## Safety rails

- **Never invent numbers.** If the fetch script fails, stop and surface
  the error.
- **Never touch anything outside METRICS.md.** This skill only writes one
  file.
- **Never commit an empty METRICS.md** if the fetch succeeded but
  returned zero rows — keep the prior version and note "no tracked
  campaigns recorded in window" at the top instead.
